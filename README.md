## :dart: O guia para alavancar a sua carreira

> SAP é o ERP mais usado por grandes empresas no mundo e, especialmente, no Brasil: bancos, indústrias, varejo e o setor público rodam processos inteiros de finanças, logística e RH em cima de sistemas SAP. Este guia reúne documentação oficial, cursos, livros, ferramentas e comunidades para quem quer entrar como consultor(a) funcional, desenvolvedor(a) ABAP/Fiori ou arquiteto(a) SAP BTP — do primeiro contato com o SAP GUI ao domínio do ABAP RESTful Application Programming Model (RAP) e do SAP S/4HANA. Um mercado com pouca concorrência de conteúdo gratuito em português e salários acima da média de TI no Brasil.

## 💡 Nossa proposta

> A proposta deste guia é dar uma ideia sobre o atual panorama e guiá-lo se você estiver confuso sobre qual será o seu próximo aprendizado, sem influenciar você a seguir os 'hypes' e 'trends' do momento. Acreditamos que com um maior conhecimento das diferentes estruturas e soluções disponíveis poderá escolher a ferramenta que melhor se aplica às suas demandas. E lembre-se, 'hypes' e 'trends' nem sempre são as melhores opções.

## :beginner: Para quem está começando agora

> Não se assuste com a quantidade de conteúdo apresentado neste guia. Acredito que quem está começando pode usá-lo não como um objetivo, mas como um apoio para os estudos. <b>Neste momento, dê enfoque no que te dá produtividade e o restante marque como <i>Ver depois</i></b>. Ao passo que seu conhecimento se torna mais amplo, a tendência é este guia fazer mais sentido e ficar fácil de ser assimilado. Bons estudos e entre em contato sempre que quiser! :punch:

## 🛠️ Ferramentas

- [SAP Cloud SDK for JavaScript/TypeScript](https://github.com/SAP/cloud-sdk-js) — SDK open source para reduzir esforço ao integrar aplicações Node.js/TypeScript com S/4HANA, SuccessFactors e outros serviços SAP.
- [OpenUI5](https://github.com/SAP/openui5) — versão open source do framework SAPUI5 para construir aplicações web enterprise responsivas (base do Fiori).
- [abapGit](https://github.com/abapGit/abapGit) — cliente Git open source para ABAP; ferramenta essencial para versionar código ABAP com Git em vez do sistema de transporte tradicional.
- [UI5 CLI](https://github.com/SAP/ui5-cli) — ferramenta de linha de comando oficial para desenvolver, buildar e servir projetos UI5/Fiori localmente.
- [SAP open-ux-tools](https://github.com/SAP/open-ux-tools) — conjunto de ferramentas e extensões (inclui SAP Fiori tools) para acelerar o desenvolvimento de aplicações Fiori elements e freestyle.
- [ABAP Development Tools (ADT) for Eclipse](https://tools.hana.ondemand.com/#abap) — página oficial de download do plugin Eclipse usado para desenvolver ABAP fora do SAP GUI clássico.
- [SAP Business Application Studio](https://help.sap.com/docs/SAP_BUSINESS_APPLICATION_STUDIO) — IDE cloud oficial da SAP para desenvolvimento full-stack (CAP, Fiori, extensões), com ambientes pré-configurados.
- [CAP — Cloud Application Programming Model (capire)](https://cap.cloud.sap) — framework oficial da SAP para construir serviços e apps cloud-native (Node.js/Java) com CDS; o site "capire" reúne toda a documentação e guias.

## 🤖 IA na prática

SAP é um dos ecossistemas corporativos onde a IA generativa mais mudou o dia a dia nos últimos dois anos — tanto dentro das próprias ferramentas SAP (Joule, sugestões de código em ABAP no ADT, SAP Build Code) quanto no uso de assistentes de código genéricos para escrever ABAP, configurar Fiori e integrar sistemas.

**Para aprender**
- Peça para explicar um erro de sintaxe ABAP ou um dump (short dump) colando o texto completo — a IA identifica a causa mais rápido do que procurar manualmente no SAP Help Portal.
- Peça para comentar, linha a linha, um relatório ABAP legado sem documentação (comum em ambientes SAP antigos) — ótimo para entender código de produção real.
- Peça exercícios práticos de RAP (ABAP RESTful Application Programming Model) com gabarito, usando o cenário de referência [SFlight](https://github.com/SAP-samples/abap-platform-refscen-flight) como base.
- Peça para traduzir conceitos entre o "ABAP clássico" (SAP GUI, transações) e o "ABAP Cloud" (RAP, Eclipse/ADT) — a mudança de paradigma confunde quem vem de SAP mais antigo.

**Para trabalhar**
- [SAP Joule](https://help.sap.com/docs/joule) — copiloto de IA generativa nativo da SAP, integrado a S/4HANA, SuccessFactors e outros produtos para consultas em linguagem natural, resumos e automações.
- [SAP Build Code](https://help.sap.com/docs/build-code) — ambiente de desenvolvimento assistido por IA generativa da SAP para gerar código CAP, Fiori e integrações a partir de descrições em linguagem natural.
- [Sugestões de código com IA generativa no ABAP Development Tools (ADT)](https://help.sap.com/docs/abap-cloud/abap-cloud/abap-code-completion-with-generative-ai) — autocomplete de ABAP treinado para o contexto do seu projeto.
- [GitHub Copilot](https://github.com/features/copilot), [Cursor](https://cursor.com/) ou [Claude Code](https://code.claude.com/docs/en/overview) — úteis para trechos de UI5/Fiori (JavaScript/TypeScript), scripts de integração e documentação de código ABAP, mesmo fora do ecossistema nativo da SAP.
- [SAP AI Core](https://help.sap.com/docs/sap-ai-core) — serviço do SAP BTP para treinar, implantar e operar modelos de IA/ML integrados a processos SAP; relevante para quem constrói extensões com IA sobre S/4HANA.

**Limites e boas práticas**
- Nunca cole dados de cliente, chaves de sistema ou trechos de código com informações confidenciais em assistentes de IA genéricos — em ambientes SAP isso costuma envolver dados financeiros e de RH sob contrato de confidencialidade.
- IA generativa inventa nomes de function modules, BAPIs e classes que parecem plausíveis mas não existem (ou existem em outra versão/release). Confirme sempre no SAP Help Portal ou com `SE37`/ADT antes de usar em produção.
- Sugestões de IA para ABAP às vezes ignoram convenções de performance específicas do HANA (ex.: processamento em massa vs. loop linha a linha). Revise com um consultor sênior antes de levar a produção.
- Ferramentas nativas da SAP (Joule, Build Code) respeitam o modelo de permissões e a governança de dados do seu tenant; assistentes genéricos, não — trate como duas categorias de risco diferentes.
